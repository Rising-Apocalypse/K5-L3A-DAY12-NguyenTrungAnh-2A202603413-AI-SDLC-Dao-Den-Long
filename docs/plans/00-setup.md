## Goal of this plan

Build the **skeleton and the full headless I/O pipeline** so that every later piece of gameplay plugs into
one `step()` function. At the end of this plan:

- `npm ci && npm run build` produces `dist/headless.js` and `dist/web/`.
- `node dist/headless.js --seed 1 --night 1 --ticks 600 --out out/a.jsonl` produces contract-shaped JSONL
  (snapshots, end line) with correct tick model, input handling, scenario loading, validation, exit codes,
  rounding and determinism. Player movement works. Motes/lanterns/shades exist as data and appear in
  snapshots, but **gameplay rules are NOT implemented yet** (no pickup, deposit, lighting, chasing, pulse,
  hits, game over, scoring). Those come in Plan 01. Leave clearly marked `// TODO(plan-01)` hooks.
- `npm run play` opens a minimal Three.js view driven by the same core.
- `npm test` and `npm run verify` pass. Harness files exist.

### Scenario application (in `createGame`)
1. Build default level from seed (lanterns, motes, shades).
2. Apply scenario: `player.pos/carried/flames` override; `random_motes:false` → motes list empty unless
   `motes` given; `random_shades:false` → shades empty unless `shades` given; `motes` (if present) replaces
   the list (ids `M1..` in listed order); `shades` (if present) replaces the list — keep a given `id`,
   otherwise assign the lowest unused `S<n>` in listed order; listed shades start in normal active state
   (`"chase"`). `lanterns` entries update by id (`pos`, `lit`, `deposited`); unknown id → `FormatError`.
   `time_left_s` sets the starting time; default `tuning.night1_duration_s`.
3. **No events, no score** during build. Score starts at 0.
4. Remember the next free shade number for future `shade_spawned` ids (deterministic).

### `step(input)` for this plan
- `tick += 1; simTick += 1; timeLeftS = startTime − simTick/60` (compute from the integer count, never
  accumulate floats).
- Movement on XZ: `dir = worldMove(input.move, input.camYawDeg)`, `pos += dir · player_speed / 60`.
- Velocity is set instantly to `dir · player_speed` (accel/stop within ≤ 0.1 s is satisfied by 0 s);
  full air control. Facing = last non-zero move direction (initially +Z).
- Jump: on rising edge of `jump` while grounded, `vel.y = JUMP_SPEED`; gravity `−GRAVITY`; land at y = 0
  only while XZ is over the island (distance from centre ≤ `ISLAND_RADIUS`).
- Off the island the player simply keeps falling (no ground). Falling penalty / respawn is Plan 01;
  for now just let y decrease (add `// TODO(plan-01): fall below y < -10`).
- Update `prevButtons`. Return `[]` events for now plus `// TODO(plan-01)` markers for: mote pickup,
  interact/deposit/light, shade AI + safe_radius, pulse/stun/push/cooldown, hits/invuln/drop, spawns,
  dawn / all_lit / no_flames, scoring.

## 4. Headless CLI (`src/headless/`)

`args.ts`: parse exactly `--seed <int>` (negative allowed), `--night <int>` (only `1` supported, else
UsageError), `--ticks <int ≥ 0>`, `--out <path>`, optional `--scenario <path>`, `--inputs <path>`,
`--snapshot-every <int ≥ 1, default 10>`. Required missing / unknown flag / non-integer → UsageError.

`cli.ts`:
1. Parse args. Read scenario/inputs files: missing/unreadable file → exit 1; invalid JSON or failed
   validation → exit 2. Message to stderr, nothing written to stdout.
2. `createGame`. Write snapshot at tick 0.
3. For k = 0..N−1: `events = game.step(timeline.at(k))`; append each event line
   `{"type":"event","tick":k+1,"name":...,"data":...}`; if `(k+1) % every === 0` append snapshot;
   if `state !== 'playing'` stop.
4. Append end line `{"type":"end","ticks":<steps executed>,"state":...,"score":...}`.
5. Create the parent dir of `--out` if needed, write the whole buffer once. Exit 0.
6. Any unexpected exception → stderr + exit 1.

Snapshot key order: `type, tick, sim_tick, state, time_left_s, score, player{pos, flames, carried},
lanterns[{id, pos, lit, deposited}], shades[{id, pos, state}], motes_active, motes[{id, pos}]`
(`motes` lists only active motes). All coordinates and `time_left_s` via `round3`.

### Validation rules → `FormatError` (exit 2)
- Inputs: top level object with `frames` array; each frame object; `tick` integer ≥ 0, strictly
  increasing; `move` array of 2 finite numbers each in [−1, 1]; `cam_yaw_deg` finite number; `jump`,
  `interact`, `pulse`, `dash` booleans if present. Unknown frame keys ignored.
- Scenario: top level object; `player.pos` 3 finite numbers; `carried`, `flames` integers ≥ 0;
  `random_motes`, `random_shades` booleans; `motes` array of 3-number arrays; `shades` array of
  `{pos: Vec3, id?: string}`; `lanterns` array of `{id: "L1".."L5", pos?: Vec3, lit?: boolean,
  deposited?: int ≥ 0}`; `time_left_s` finite number ≥ 0. Unknown top-level keys ignored.

## 5. Web (`src/web/`) — minimal, functional, not polished

`index.html` + `main.ts` + `hud.ts` + `render.ts`. Uses `createGame` from core with the same
`step()` on a fixed-timestep accumulator (60 Hz, max 5 steps per frame). Scene: night sky, round island
(radius `ISLAND_RADIUS`), Mây = capsule + conical hat + small warm lantern; Great Lanterns = posts with a
lamp (warm emissive when lit, dim otherwise); motes = small glowing yellow spheres hovering ~0.5 m;
shades = dark purple spheres. Third-person camera behind the player; camera yaw changed by mouse drag or
Q/E; build `InputState` with `camYawDeg` = camera yaw using the **same convention as the contract**
(yaw 0 → forward input `z=1` goes +Z). Keys: WASD/arrows move, Space jump, E interact, F pulse, R restart.
HUD (DOM overlay): time left, score, flames, carried/capacity, lanterns lit x/5, state banner.
Seed for interactive play: from URL `?seed=` else a fixed default (1).
`src/extras/index.ts`: exports `EXTRAS: Extra[] = []` and the `Extra` interface (hooks:
`onBuild(state, rng)`, `onStep(state, input, rng)`), documented as "web only, never loaded by headless".
Web passes `EXTRAS`; headless passes nothing.
